# Как написать кейс

Один файл на кейс: `scenarios/<id>.js`, CommonJS-модуль `module.exports = { ... }`. Он —
единственный источник правды: из него строятся проектор, телефоны ролей, пульт и карточки для печати.
Сервер загружает все паки из `scenarios/` при старте; пак с ошибками пропускается с сообщением в логе.

Проверка во время работы:

```bash
node tools/validate.js scenarios/my-case.js     # или npm run validate — все паки
```

## Формат

```js
module.exports = {
  meta: {
    id: 'my-case',            // латиница, цифры, - и _
    title: 'Название кейса',
    brief: 'Одна строка для лобби',
    difficulty: 'средняя',
    etaMin: 35,               // минут игры
    moneyLimit: 4000000,      // ₽: полная шкала потерь на проекторе
  },
  roles: {                    // ровно пять, id фиксированы, названия только по-русски
    commander: { name: 'Командир инцидента', mission: '…', welcomePrivate: '…' },
    scout:     { name: 'Скаут наблюдаемости', mission: '…', welcomePrivate: '…' },
    engineer:  { name: 'Инженер платформы', mission: '…', welcomePrivate: '…' },
    domain:    { name: 'Доменный специалист', mission: '…', welcomePrivate: '…' },
    comms:     { name: 'Связной с бизнесом', mission: '…', welcomePrivate: '…' },
  },
  diagram: {                  // одна схема на кейс, холст 640×320
    nodes: [{ id: 'edge', label: 'edge-gateway', x: 182, y: 136, w: 150, color: 'red', note: '5xx 92%' }],
    edges: [{ from: 'clients', to: 'edge', label: 'HTTPS' }],
  },
  steps: [{
    id: 'p1', title: 'Алерт',
    brief: 'Публичный текст ситуации — читает зал',
    question: 'С чего начинаем?',
    focus: ['edge'],                       // компоненты, о которых шаг
    state: { edge: 'yellow' },             // необязательно: как схема выглядит на этом шаге
    private: {                             // для каждой из пяти ролей
      scout: { data: 'сырые данные, артефакты', deliver: 'что донести команде' },
      // …
    },
    options: [{                            // 2–4 варианта
      id: 'p1a', label: 'Текст варианта',
      effects: { tension: -5, money: 300000, ttrMin: 2 },
      score: 2,
      trap: false,
      revealText: 'Что случилось — проектор',
      debrief: 'Для мини-разбора — ведущему',
    }],
    hint: 'Как подать шаг — ведущему',
  }],
  end: {
    grades: [                              // абсолютные очки, сверху вниз
      { min: 18, label: 'Образцово', text: '…' },
      { min: -99, label: 'Разбор полётов', text: '…' },
    ],
    rootCause: 'Причина и правильная цепочка — проектор в финале',
    debriefQuestions: ['Вопрос залу', '…'],
  },
};
```

## Кто что видит

| Поле | Проектор | Телефон роли | Пульт |
| --- | --- | --- | --- |
| `brief`, `question`, `options[].label` | да | да | да |
| `private[роль]` | нет | только своя | все пять |
| `score`, `trap`, `effects`, `debrief`, `hint` | нет | нет | да |
| `revealText`, вердикт, очки, сдвиг шкал | после раскрытия | после раскрытия | да |
| `rootCause` | в финале | нет | в финале |

Сервер отправляет каждому экрану только его часть: приватка и флаги ловушек не попадают
в браузер проектора и чужих телефонов даже в сетевом трафике.

## Правила валидатора

- ровно пять ролей с фиксированными id, у каждой `name`, `mission`, `welcomePrivate`;
- у каждого шага `title`, `brief`, `hint` и приватный блок (`data` + `deliver`) на каждую роль;
- 2–4 варианта; у каждого `label`, `revealText`, `debrief`, числовые `score` и `effects.tension/money/ttrMin`;
- **ровно один лучший вариант** на шаг: уникальный максимум `score`, и он не ловушка;
- вариант, чей `debrief` начинается со слова «Ловушка», обязан иметь `trap: true`;
- `focus` и `state` ссылаются на компоненты диаграммы, цвета — `red`, `yellow`, `green`, `gray`;
- `end.grades`: нижний порог не выше минимально возможного счёта (очки бывают отрицательными —
  ставьте `-99`), верхний достижим.

## Вердикт варианта

Вычисляется движком, в паке его нет: `trap` — «Ловушка»; максимум очков — «Лучший ход»;
`score > 0` — «Приемлемо»; иначе — «Слабый ход». Вердикт видит и зал.

## Как писать хороший кейс

- **Асимметрия информации.** Лучший ответ должен складываться из данных двух-трёх ролей.
  В `debrief` назовите, чьи данные вели к ответу: ведущему проще разбирать.
- **Ложные следы допустимы:** «всё зелёное» у одной роли при красном у другой — сильный момент.
- **Проектор не подсказывает.** `brief`, `question` и `label` не содержат «правильно» и «ловушка»
  (это проверяет тест). Ожидаемое поведение — в `hint` и `debrief`.
- **Командир систем не видит:** его `data` — доска гипотез, давление стейкхолдеров, ограничения;
  `deliver` — что он должен потребовать или решить. **Связной** — тикеты, чат, статус-страница, звонки.
- **SRE-практики:** откат свежего релиза — законная обратимая мера (+1, не ловушка);
  сначала снять влияние самым быстрым безопасным путём, причину — потом; разбор без поиска виноватых;
  Командир не уходит с бриджа без явной передачи; лучший ход первого шага включает первый статус клиентам
  («Investigating» и время следующего обновления). Mitigated и Resolved — строго по определениям из
  [руководства ведущего](facilitator-guide.md#игра-и-настоящий-инцидент): незакрытая корневая причина
  сама по себе не мешает Resolved, мешает конкретный ближайший риск. Окна наблюдения в игре короткие —
  в разборе отметьте, что в жизни это 15–60 минут.
- **Фактура проверяема:** конфиги, команды и числа — как в настоящих системах (семантика параметров Istio,
  Postgres, Kafka и т. п.); бренды — вымышленные.
- **Метрики правдоподобны:** лучший путь укладывается в `moneyLimit`, путь ловушками его пробивает
  (это проверяет тест), сумма `ttrMin` по лучшему пути ≈ длительности инцидента в документе ведущего.
- **Числа совпадают** с документом ведущего, если он есть: тест сверяет список ключевых фактов
  (`test/packs.test.js`, массив `facts`). Для кейса без документа фактура живёт только в паке.
- **Диаграмма:** между соседними блоками оставляйте ≥ 40 px — иначе подпись ребра не поместится и не будет показана.
- **Порядок в каталоге** — по `difficulty` (лёгкая → средняя → высокая), внутри — по названию.

## Как добавить кейс

1. Создайте `scenarios/<id>.js`, прогоните `node tools/validate.js scenarios/<id>.js`.
2. Добавьте кейс в `CASES` в `test/packs.test.js` (тест падает, если в `scenarios/` есть пак вне списка).
   Если у кейса есть документ ведущего (markdown), укажите `doc` и `facts` — ключевые подстроки, общие для пака и документа.
3. `npm test`, затем сыграйте кейс целиком: `npm start`, пульт и проектор в двух вкладках.
