# Единый воркшоп: один пак, три экрана — план реализации

**Спека:** `docs/superpowers/specs/2026-10-09-unified-workshop-design.md` (обязательна).
**Цель:** заменить холл и war-room одним пошаговым воркшопом на сервере: проектор, телефоны
пяти ролей, пульт ведущего. Один пак на кейс.

**Архитектура:** чистый UMD-движок `workshop-engine.js` (валидатор, команды раунда, подсчёт,
представления для трёх аудиторий, итоги). Сервер авторитетен: принимает команды, применяет их
движком, хранит состояние в `state.json` и шлёт по SSE **каждому клиенту своё представление**.
Браузер паки не загружает: приватка и флаги ловушек не уходят туда, где их не должно быть.

## Решения по неясностям спеки

| Место спеки | Решение | Почему |
| --- | --- | --- |
| «переиспользуется текущий server.js» | Сервер переписан на команды (`POST /api/cmd`) и представления по аудиториям (`/events?view=screen|play|gm`) | Текущий сервер шлёт всё состояние всем — приватка всех ролей и голоса были бы видны в любом телефоне |
| `step.diagram` на каждом шаге | Одна `diagram` на кейс (как в холле) + у шага `focus` и `state` (перекраска компонентов) | Иначе диаграмма копируется 10 раз — то самое дублирование, с которым спека борется. `state` закрывает пункт роадмапа №8 |
| `effects: { moneyMin }` | `effects: { tension, money, ttrMin }`, `money` — потери в ₽ | `moneyMin` читается как минуты |
| `meta.moneyLimit` | Шкала потерь на проекторе: 100% = лимит, сверх лимита — красным | Иначе поле ни на что не влияет |
| Правило «hint не начинается со «Ловушк»» | Вариант, чей `debrief` начинается с «Ловушк», обязан иметь `trap: true`; у ловушки score ниже лучшего | Правило в спеке перевёрнуто относительно текущего теста, а `hint` в новом формате у шага, не у варианта |
| `end.grades` покрывает 0..maxScore | Пороги `min` — абсолютные очки; нижний порог ≤ минимально возможного счёта (очки бывают отрицательными) | Ловушки «найти виноватого» дают −1 |
| «проектор `#screen` + PIN» | Проектор без PIN | Он только читает и не видит ничего секретного |
| Фаза `debrief` | Нет отдельной фазы: мини-разбор идёт на `revealed`, ведущий видит `debrief` варианта | Проектор в обеих фазах одинаков, вторая кнопка — лишний клик |
| Захват роли «кто первый» | Токен роли на устройстве (`localStorage`), перезагрузка телефона возвращает роль; ведущий освобождает роль | Пункт роадмапа №16 и защита от случайного захвата |
| Ничья | Если голос Командира среди лидеров — он и решает автоматически; иначе ведущий выбирает вариант на пульте | Привилегия Командира уже выражена его голосом |
| Голос дважды | Голос окончательный; ведущий может открыть повторное голосование или вписать голос молчащей роли | Тест «невозможность голоса дважды» из спеки |
| QR на проекторе | Крупный адрес `http://<ip>:<port>/#play` вместо QR | QR-кодер без зависимостей — сотни строк; в роадмап |

## Роадмап в этой работе

- №4 глобальный перехват ошибок рендера → во всех трёх экранах.
- №5 CLI-валидатор → `node tools/validate.js scenarios/x.js`.
- №7 таймер шага → таймер фазы на проекторе и пульте (мягкий, без автоперехода).
- №8 состояние диаграммы по шагам → `step.state`.
- №16 переподключение игрока и освобождение роли.
- №6, 12, 13, 14, 17 теряют смысл (war-room и холл удалены, сервер авторитетен) — вычёркиваем.
- №10, 11, 15 и QR — остаются в роадмапе.

## Задачи

1. **Движок** `workshop-engine.js` + `test/workshop-engine.test.js`:
   validate, maxScore/minScore, createSession, apply(cmd, now), tally, view(audience), summary, report.
   → проверка: тесты на правила пака, тай-брейк, кворум, откат, метрики, оценки, двойной голос.
2. **CLI-валидатор** `tools/validate.js` → проверка: на битом паке код выхода 1 и список ошибок.
3. **Паки** `scenarios/phantom-network.js`, `scenarios/expired-cert.js` в новом формате
   (скелет из hall-паков, приватка из war-room паков и markdown) → проверка: validate = [],
   прохождение лучшими и худшими вариантами, ключевые числа совпадают с markdown.
4. **Сервер** `server.js`: команды, представления, токены ролей, PIN, state.json, архив, `/healthz`,
   `/api/info` (адреса для телефонов) → проверка: `test/server.test.js` (фазы, SSE, PIN, утечки, восстановление).
5. **UI** `index.html` + `ui/*.js` (`#screen`, `#play`, `#gm`, `#cards`) по скиллу `inc-workshop-ui`
   → проверка: `npm run test:ui` на три экрана + просмотр скриншотов.
6. **Удаление** war-room, холла, старых паков и тестов; Dockerfile, CI.
7. **Документация**: README, facilitator-guide, scenario-authoring, architecture, roadmap, CHANGELOG 2.0.0, CLAUDE.md.
