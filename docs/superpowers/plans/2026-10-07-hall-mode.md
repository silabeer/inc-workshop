# Холл-режим «Решение за решением» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** простой в зале интерактивный режим воркшопа: два соревнующихся командных счёта, граф решений, один HTML-файл без сервера.

**Architecture:** чистое ядро `hall-engine.js` (UMD, как `engine.js`) с валидацией и применением ходов; контент — plain-скрипты с глобальным коллектором `HALL_SCENARIO(...)` (идиома существующих паков); UI — один самодостаточный `hall.html`, работающий по file://.

**Tech Stack:** vanilla JS (ES2020), node:test, без зависимостей и сервера.

**Spec:** `docs/superpowers/specs/2026-10-07-hall-mode-design.md`

## Global Constraints

- Git-репозитория нет — коммитов нет, верификация только через `node --test --test-force-exit` (macOS, GNU timeout отсутствует).
- Тесты: `node:test` + `node:assert/strict`, имена тестов на русском (идиома `test/engine.test.js`).
- `hall-engine.js` — UMD-обёртка как в `engine.js:3-6`: в браузере глобал `HALL_ENGINE`, в Node `module.exports`.
- Сценарии — plain-скрипты БЕЗ ES-модулей (Chrome блокирует их на file://); регистрация через вызов глобальной функции `HALL_SCENARIO(obj)`; в браузере её определяет `hall.html`, в тестах — стаб.
- Весь UI-текст на русском. Очки вариантов: лучший +2, приемлемый +1, плохой 0, катастрофа −1.
- Tension: старт 50, диапазон 0–100 (кламп), пороги цвета в UI: <40 зелёный, 40–70 жёлтый, >70 красный.
- НЕ изменять: `war-room.html`, `server.js`, `engine.js`, `scenarios/phantom-network.js`, `scenarios/expired-cert.js`, существующие тесты.

## Review Focus

1. `choose` после `ENDED` (ведущий дважды жмёт клавишу) → исключение — тест в Task 1.
2. Равенство очков на финале → `winner: 'draw'` — тест в Task 1.
3. Tension за границами 0–100 после выбора → клампится — тест в Task 1.
4. Битый `goto` или недостижимый `end` в контенте кейса → `validate` ловит, pack-тест падает — Task 2 и 3.
5. file://-безопасность UI: ни `fetch`, ни `localStorage`, ни ES-модулей — статический тест в Task 4.

### Task 1: hall-engine.js — ядро

**Files:**
- Create: `hall-engine.js`
- Test: `test/hall-engine.test.js`

**Interfaces:**
- Consumes: ничего (первый модуль).
- Produces (используют Tasks 2–4):
  - `validate(scn) → string[]` — ошибки: `нет start`, `стартовый узел X не найден`, `узел X: вариант Y → несуществующий узел Z`, `узел X: должно быть 2–4 варианта`, `из узла X недостижим ни один end`.
  - `createGame(scn, opts?) → state`, `opts.teams?: [string, string]` (дефолт `['Команда А', 'Команда Б']`).
  - state: `{scenarioId, nodeId, turn: 0|1, teams: [string, string], scores: [number, number], tension: number, log: Array, status: 'ACTIVE'|'ENDED', winner: null|0|1|'draw'}`; log-запись: `{nodeId, choiceId, team, gained, tension}`.
  - `choose(state, choiceId) → {state, result}`; result: `{team: 0|1, choice, gained, tension}`. Не мутирует входной `state`. Бросает `Error` на неизвестном `choiceId` и на `state.status === 'ENDED'`.

- [ ] **Step 1: Написать failing-тесты `test/hall-engine.test.js`**

Фикстура-сценарий прямо в файле (3 узла: старт с 2 вариантами → промежуточный → end; плюс вариант-катастрофа с `score: -1`). Тесты:
- `validate` на валидной фикстуре → `[]`; на битом `goto`; на отсутствующем `start`; на узле с 1 вариантом; на недостижимом `end` (ветка без выхода) → непустой массив с сообщением.
- `createGame` → `turn 0`, `scores [0,0]`, `tension 50`, `status 'ACTIVE'`, `winner null`, дефолтные имена; с `teams` — переданные имена.
- `choose` валидный → очки начислены ходящей команде (scores[0]), ход переключился на 1, tension изменилась на дельту исхода.
- `choose` не мутирует входной state (входной `scores`/`nodeId` прежние).
- `choose` с неизвестным `choiceId` → throws.
- `choose` при `status 'ENDED'` → throws.
- tension кламп: выбор с `tension: -100` от старта 50 → 0; затем выбор с `tension: +200` → 100.
- Проход до `end` → `status 'ENDED'`; победитель по очкам; при равенстве — `winner: 'draw'`.

- [ ] **Step 2: Прогнать — убедиться, что падает**

Run: `node --test --test-force-exit test/hall-engine.test.js`
Expected: FAIL (`Cannot find module '../hall-engine.js'`).

- [ ] **Step 3: Реализовать `hall-engine.js`**

UMD-обёртка как в `engine.js:3-6`. `validate`: проверить `start`, для каждого узла — 2–4 варианта и существование всех `goto`; достижимость `end` — DFS с посещёнными узлами от каждого узла. `createGame` — собрать state по спеке. `choose` — найти узел и вариант, собрать новый state (копия log, scores, tension с клампом `Math.min(100, Math.max(0, ...))`), при `end`-узле вычислить `winner`. Без DOM, дат, хранилищ.

- [ ] **Step 3: Реализовать `hall.html`**

Один файл: стили в `<style>` (тёмная тема в духе war-room.html, крупный шрифт для проектора), инлайн-скрипт в конце. Структура экранов — div-ы с переключением видимости:
1. Лобби: заголовок, карточки кейсов из `HALL_SCENARIOS` (title + brief), два поля имён команд (дефолт «Команда А»/«Команда Б»), кнопка «Старт».
2. Игровой: заголовок кейса, бейдж чей ход + рамка у счёта ходящей команды, tension-полоса с цветом по порогам, карточка узла (title, text), кнопки вариантов с цифрами 1–4, панель счёта двух команд, в углу мелко — `say` текущего узла.
3. Последствия: outcome, «+N — команде X», дельта tension, мелко `hint`, кнопка «Дальше».
4. Финал: текст end-узла, счёт, вердикт («Победила команда X» / «Ничья»), кнопка «Заново» → лобби (имена остаются в полях).

Логика: состояние держится в одном объекте `state` + ссылка на текущий сценарий; `render()` перерисовывает экран; кнопка варианта зовёт `HALL_ENGINE.choose` и прячет кнопки (двойной клик невозможен). Горячие клавиши: 1–4 — выбор на игровом экране, Enter/→ — «Дальше», R — в лобби. Без сети и хранилищ — только в памяти.
