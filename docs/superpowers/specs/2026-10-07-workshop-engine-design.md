# Дизайн: сценарно-независимый движок интерактивного воркшопа

Дата: 2026-10-07
Статус: дизайн утверждён пользователем, ожидает ревью spec

## 1. Контекст и цель

Репозиторий — приложение для проведения настольного SRE-воркшопа: `server.js` (хранилище состояния + SSE, без зависимостей) и `war-room.html` (движок, контент и рендер в одном файле, ~1000 строк). Сейчас движок жёстко привязан к одному сценарию «Фантомная сеть» v3.1; учебный сценарий «Просроченный сертификат» существует только как GM-документ (`expired-certificate-training.md`).

Цель: приложение проводит воркшоп по любому сценарию из контент-пака. GM выбирает кейс и режим в лобби; игроки заходят с телефонов; расписание сценария (звонок CIO, ивенты мира, исполнение действий, паника, деньги) исполняет автопилот; GM сохраняет роли судьи (K-улики, оценка апдейтов, спорные моменты) и ведущего.

Принятые решения (пользователь): автопилот по расписанию из пакета (уровень 1A); контент-паки — отдельные `.js`-файлы (2A); учебный режим с подсказками нужен; вычистить всё, что сейчас делается руками.

## 2. Границы

Не делаем (сознательно, следующие этапы): редактор сценариев в приложении; движок на сервере (автономная работа без открытых вкладок); комнаты на 9+ игроков; авторизацию; мультиязычность; сборку/бандлер — проект остаётся нулевых зависимостей, запускаемым и как `node server.js`, и открытием файла.

## 3. Формат контент-пака

Каталог `scenarios/`, один файл на кейс. Файл саморегистрируется через глобальную функцию `SCENARIO(obj)`, движок складывает объект в реестр `SCENARIOS`. Подключение — статическим `<script>`-тегом в `war-room.html`: новый кейс = новый файл + один тег. Никакого сканирования каталога (оно не работает в file://-режиме).

Полная схема пакета:

```js
SCENARIO({
  id: 'expired-cert',            // уникальный, используется в URL архива
  title: 'Просроченный сертификат',
  version: '1.0',
  slot: 'учебный, слот 35 минут',// описание для лобби

  durationSec: 720,              // жёсткий стоп; без стабилизации -> FAILED
  winHoldSec: 60,                // окно победы: err <= winErrPct столько секунд
  winErrPct: 5,                  // необязательно, по умолчанию 5

  money: {
    basePerMin: 150000,
    failAt: 3000000,             // сожжено столько -> FAILED
    stabilizeAtMult: 0.3,        // mult телеметрии <= порога = стабилизация (-3 паники)
  },

  panic: {
    tiers: [                     // name, mult потерь, cost = множитель цен запросов
      {min:0,  max:4,  name:'Штатный сбой',            mult:1, cost:1},
      {min:5,  max:9,  name:'Повышенная тревога',      mult:2, cost:1.5},
      {min:10, max:14, name:'Критический эскалейшн',   mult:4, cost:1.5},
      {min:15, max:18, name:'Неконтролируемый шторм',  mult:4, cost:1.5},
      {min:19, max:20, name:'Meltdown',                mult:4, cost:1.5},
    ],
    autoEverySec: 180,           // +1 паники каждые столько игровых секунд
    silenceAfterSec: 240,        // +1 если тишина дольше (счётчик по статус-апдейтам)
    meltdownAt: 20,              // паника >= значения запускает отсчёт
    meltdownHoldSec: 90,         // держится столько -> FAILED
  },

  schedule: {
    cioCall: {                   // или null
      atSec: 120, durationSec: 90, panicEverySec: 45,
      caller: 'Александр (CIO)',
      lines: [ /* реплики для GM */ ],
    },
    worldEvents: {
      rollsAt: [360],            // игровые секунды бросков d10
      table: [                   // индекс = результат d10; null = тихо
        null,
        {t:'...', d:'...', fx:'storm'},      // fx см. ниже
        {t:'...', d:'...', fx:'scout-x2'},
        {t:'...', d:'...', fx:'panic1'},
        {t:'...', d:'...', fx:'transient', transientSec:30},
      ],
    },
  },

  roles: { /* roleId: {name, short, color, desc, limit} */ },
  roleOrder: ['commander','scout','platform','domain','comms'],

  startScreens: { /* roleId: string */ },

  artifacts: [                   // id уникальны внутри пакета
    {id:'S1', role:'scout', tool:'...', cost:20,
     key:null,                   // или 'K1'..'K4' — подсветка у GM
     decoy:false,
     body:`...`,
     followUp:{delay:180, body:`...`}},   // необязательно (C4 в основном кейсе)
  ],

  mitigations: [
    {id:'M-P1', role:'platform', title:'...', cost:90,
     review:true,                // требует ревью вторым инженером (+30 с)
     trap:false,                 // ловушка: паника +2
     hint:'...',                 // подсказка в меню действий
     // apply — необязательный хук нестандартного эффекта:
     // apply(appliedSet:Set, game) -> {add?:string[], remove?:string[],
     //                                 set?:object, transientSec?:number,
     //                                 msg?:string, sev?:string}
     // Без хука действие просто добавляет свой id в game.applied,
     // а телеметрия пакета это интерпретирует.
    },
  ],

  // Чистая функция: состояние -> телеметрия для проектора и экономики.
  telemetry: (game) => ({err:7, rps:2000, pool:'50/50', poolN:50,
                         gor:210, mult:1.0, label:'Инцидент'}),

  hints: {                       // учебный режим; необязательно
    scout: ['Прочитай стартовый экран вслух команде.',
            'Запроси один инструмент из меню и подожди цену.',
            'Проговори вывод командой и вынеси на стену (140 знаков).'],
    // ... остальные роли
  },
  trainingOverrides: {           // необязательно; мягче расписание для новичков
    panic: {autoEverySec: 360, silenceAfterSec: 300},
  },

  cheatsheet: `...`,             // шпаргалка на пульте GM
});
```

Эффекты ивентов (`fx`) — закрытый набор движка: `storm` (потери +20% до апдейта на 2 из 3), `panic1` (+1 паники), `scout-x2` (следующий запрос Scout ×2 по цене, флаг сжигается при запросе), `transient` (телеметрия «дышит» `transientSec` секунд).

## 4. Протокол записи с условным rev

Состояние обрастает счётчиком `rev` верхнего уровня. Сервер инкрементирует `rev` на каждой успешной записи; клиент в `POST /write` передаёт `expectRev`. Не сошлось — ответ `409` без изменений состояния; клиент ждёт свежее состояние по SSE и пересчитывает.

Это убирает гонки автопилота между одновременно открытыми вкладками (пульт GM и проектор): планировщик идемпотентен по маркерам в состоянии, условная запись гарантирует, что эффект применён ровно один раз. Заодно лечит одновременный клейм роли двумя игроками. В file://-режиме (localStorage + BroadcastChannel, одна вкладка-источник правды) rev не используется — записи безусловны.

Формат ответа сервера: `204` при успехе (новое состояние придёт по SSE), `409` при рассинхроне, `400` как раньше.

## 5. Автопилот: чистый планировщик + исполнитель

Новый файл `engine.js` — universal-модуль (работает в браузере и в Node, ради тестируемости). Только чистые функции, никакого DOM и сети:

- `gameSec(game, now)`, `burned(game, now)` — переносятся из текущего кода без изменений семантики (пауза, сегменты ставки);
- `tierOf(panic, tiers)`, `currentRate(game, pack, now)` — экономика через поля пакета;
- `planAutopilot(state, pack, now) → {patch, events, panicOps} | null` — одна слитая запись в тик.

Обязанности планировщика (по состоянию, пакету и игровому времени; все срабатывания помечаются в `game.fired`, повторов нет):

1. **Авто-паника:** +1 каждые `panic.autoEverySec`; +1 за тишину дольше `silenceAfterSec` (по `lastStatusAt`, счётчик сбрасывается флагом как сейчас).
2. **Звонок CIO:** старт в `cioCall.atSec` (оверлей + звук уже есть); во время звонка +1 каждые `panicEverySec` без ответа; таймаут в конце `durationSec` → результат `timeout`. Завершение «отбит/провален» — ручное (GM/Comms).
3. **Ивенты мира:** в каждый момент из `rollsAt` — один бросок d10, применение `fx`, запись в ленту. Ручной бросок у GM сохраняется как override (вручную можно, автоматически — не дважды).
4. **Исполнение действий:** предложение в статусе `go` с `goAt` считается выполненным в `goAt + cost (+30 с при ревью)` игровых секунд; планировщик применяет эффект: хук `apply` или дефолт «добавить id в `applied`», затем: ловушка → +2, действие без улик → +2, стабилизация (mult упал до `stabilizeAtMult` или ниже) → −3 один раз. Статус предложения → `done`. GM сохраняет: отклонить, ручное применение/снятие эффекта, кнопку «выполнить немедленно».
5. **Условия конца:** `durationSec` без стабилизации → FAILED; паника `meltdownAt` на `meltdownHoldSec` → FAILED; `burned ≥ money.failAt` → FAILED. Победа не автоматическая: при `err ≤ winErrPct` подряд `winHoldSec` на пульте и проекторе загорается «условия победы выполнены»; Resolved жмёт GM по объявлению IC.

Исполнитель — любая открытая вкладка (пульт или проектор): раз в ~1 с считает план, шлёт условную запись, при `409` молча ждёт SSE. GM может закрыть ноутбук — проектор продолжит вести игру.

## 6. Учебный режим

В лобби GM выбирает режим: `standard` или `training` (`game.mode`). В training:

- у каждой роли во вкладках появляется «Подсказки» — нумерованный чек-лист из `pack.hints[role]`; текущий пункт подсвечивается простыми счётчиками (сколько артефактов получено, есть ли пины на стене, есть ли предложения действий);
- пульт и проектор показывают плашку «УЧЕБНЫЙ РЕЖИМ»;
- применяются `trainingOverrides` (например, реже авто-паника).

Интерфейс остальной идентичен стандартному: новичок играет в настоящий интерфейс, а не в отдельный тренажёр.

## 7. Архив и история игр

Сброс больше не стирает: клиент шлёт `{reset:true, archive:{scenarioId, mode, status, endedSec, burned, at}}`; сервер, если в состоянии было что-то (игра начата или непусты wall/hypotheses/proposals/statuses), пишет полный снапшот в `archive/<ISO-дата>-<scenarioId>.json` рядом со сводкой.

Интерфейс: на домашнем экране и на пульте — «История игр» (`GET /archive` — список сводок; `GET /archive/<file>` — полный снапшот). По клику: read-only таймлайн из архивного состояния и повторная выгрузка постмортема `.md` (buildReport рефакторится на приём состояния аргументом). Кнопка «Играть снова» — возврат в лобби с тем же пакетом. В file://-режиме архив скрыт (localStorage одной вкладки).

## 8. Лобби и выбор сценария

`game` обрастает полями `scenarioId` и `mode`. Домашний экран и пульт в статусе LOBBY показывают карточки зарегистрированных пакетов (название, версия, слот) и переключатель режима. Старт инцидента берёт пакет из реестра; проектор в лобби показывает выбранный кейс и QR/ссылку для игроков. Reset возвращает в LOBBY с пустым `scenarioId`.

## 10. Миграция и совместимость

Это первая версия формата (`engine: 1` в пакете не заводим — реестр и схема единственные). Старый `state.json` несовместим: при старте сервера файл без `rev` и `scenarioId` игнорируется (как сейчас при битом JSON) — достаточно нажать «Сбросить всё» в лобби. Никаких данных для сохранения нет: продуктивных игр ещё не было.

## 11. Тестирование

Фреймворк не подключаем: `node --test` (встроен, Node 18+). Критерии приёмки:

1. `node --test` зелёный.
2. Прогон «Просроченного сертификата» (http-режим, 2 роли + пульт + проектор): звонок сам стартует на 2-й минуте; d10 сам на 6-й; после «Go» на M-P1 эффект применяется сам через 90 с; паника и сожженные деньги бьются с документом кейса; Resolved → архив появляется в «Истории игр», `.md` скачивается.
3. Прогон «Фантомной сети»: расписание 240/420/900; авто-исполнение M-D2 → M-P3 даёт стабилизацию и −3 паники; ловушка T-POOL даёт +2 и телеметрию из её строки.
4. file://-режим: лобби и игра работают, архив скрыт, rev не требуется.
5. Сверка пакетов с GM-документами по чек-листу: цены, ключи K1–K6/K1–K4, таблицы телеметрии, расписание, пороги FAILED — совпадают с `phantom-network-asymmetric.md` и `expired-certificate-training.md`.
