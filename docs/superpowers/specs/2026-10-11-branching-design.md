# Ветвления: сюжет помнит, что команда выяснила

Дата: 2026-10-11
Статус: эскиз на будущее, не в работе

## Проблема

Игра линейная: шаг N+1 наступает после шага N при любом выборе. Поэтому поздние шаги сообщают
находки расследования, даже если команда пошла по ложному следу: dns-ttl p5 объявляет старые адреса,
expired-cert c3 — истёкший сертификат, disk-full p5 — удалённый открытый журнал, retry-cascade p4 —
повторы в mesh. В 2.5 это закрыто текстом («пока бридж спорил, дежурный инженер нашёл…»): находка
приходит со стороны, и сюжет не противоречит выбору. Но команда, которая сама докопалась до причины, и
команда, которой её подсказали, получают одну и ту же игру — разница видна только в очках и шкалах.

Цель: команда, не нашедшая факт, не получает его даром — или получает с ценой (время, деньги, давление).

## Варианты

### A. Варианты текста по прошлому выбору

Шаг хранит альтернативные `brief` (и при нужде `private`) по выбранным ранее вариантам:

```js
{ id: 'p5', brief: 'По умолчанию…', briefIf: [{ after: ['p4b', 'p4c'], brief: 'Перевыпуск ничего не дал…' }] }
```

- Движок: при построении представления смотрит в `journal` и подставляет первый подходящий текст.
- Плюсы: структура, очки, аналитика, карточки не меняются; ~полдня на движок.
- Минусы: условия по id вариантов хрупкие и не масштабируются (на 9 шагах комбинаций много);
  находка всё равно наступает — меняется только подача.

### B. Знания команды (флаги) + обходные шаги — рекомендуемый

Вариант может давать знание, шаг — требовать его:

```js
options: [{ id: 'p4a', …, learns: ['open-files'] }],
steps: [
  { id: 'p5', needs: ['open-files'], … },                     // основной путь
  { id: 'p5-detour', detour: true, gives: ['open-files'],      // если знания нет — сначала этот шаг
    title: 'Место всё ещё пропадает', … },
]
```

- `state.knows` — множество знаний; пополняется при раскрытии (`learns`) и после обходного шага (`gives`).
- При `next`: если у следующего шага `needs` не покрыты — вставляется обходной шаг, который их даёт
  (дороже по времени/деньгам: команда добывает факт заново, уже под давлением). Обходные шаги в
  линейный счёт шагов не входят.
- Тексты шагов могут ссылаться на знание: `briefIf: [{ knows: 'open-files', brief: … }]` — условия по
  смыслу, а не по id вариантов.
- Плюсы: сюжет честный — «не нашли — придётся найти»; знания переживают переименование вариантов;
  скелет кейса остаётся линейным, валидатор проверяет конечный набор путей.
- Минусы: очки становятся путезависимыми (обходной шаг — дополнительные очки/штраф), «шаг N из M»
  меняется на «шаг N» или M считается по пути; контент — 1–2 обходных шага на кейс.

### C. Полный граф шагов

`option.next = stepId`, шаги — направленный граф без циклов, конец — терминальные шаги.

- Максимальная гибкость (разные концовки, разные развязки).
- Цена — всё: `stepIndex` → `stepId`, `maxScore/minScore` и пороги оценок по путям, валидатор
  достижимости, аналитика по шагам с разной долей прохождения, «шаг N из M», печатные карточки
  (ведущему нужна карта веток), откат, миграция `state.json`, кратный рост контента (тексты ×5 ролей
  на каждую ветку). Для 30–40-минутного воркшопа избыточно.

## Что задевает B (план работ)

| Где | Что |
| --- | --- |
| Движок | `knows` в сессии и снимках; `learns`/`needs`/`gives`/`detour` в валидаторе (каждый `needs` кто-то даёт; обходной шаг даёт то, чего ждёт следующий); выбор следующего шага в `next`; `briefIf` в представлениях; откат — как сейчас, по снимкам |
| Очки и оценки | `maxScore` — по лучшему пути (без обходов), `minScore` — по худшему (со всеми обходами); пороги `grades` проверяются на обоих |
| Сервер | миграция сохранённой партии: нет `knows` → вычислить из `journal` |
| Пульт | «Дальше: обходной шаг „…“» и почему (каких знаний нет); заметка ведущего к обходному шагу |
| Проектор и телефоны | «шаг N» без «из M» на обходном шаге; приватка обходного шага |
| Итоги, отчёт, архив, аналитика | обходной шаг в журнале с пометкой; аналитика: доля партий, попавших в обход, — сильная метрика для разбора («60% команд не нашли открытые файлы сами») |
| Печать | обходные шаги — отдельной стопкой с пометкой «если не выяснили…» |
| Паки | по 1–2 знания на кейс там, где сейчас находка «приходит со стороны» (5 мест из 2.5), и по обходному шагу на каждое |
| Тесты | путь «лучший» без обходов, путь «худший» со всеми обходами, валидатор `needs`/`gives`, миграция state.json, UI обходного шага |

Оценка: движок, сервер, UI и тесты — M (3–4 дня); контент обходных шагов — S на кейс.

## Рекомендация

Начать с B на одном кейсе (disk-full: знание «открытые файлы» после p4 и обходной шаг перед p5),
сыграть на живой группе и только потом раскатывать на остальные. A не делать — это то же, что
текстовое решение 2.5, но дороже. C — только если появится запрос на разные концовки.
