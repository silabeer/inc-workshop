# Единый интерактивный воркшоп: один пак, три экрана

Дата: 2026-10-09
Статус: дизайн утверждён, перед реализацией

## Контекст и цель

В репозитории живут два разных продукта на похожем контенте: холл-режим
(`hall.html` + `hall-engine.js`, пошаговый, без сервера) и war-room
(`war-room.html` + `engine.js` + `server.js`, реалтайм с телефонами).
Контент каждого кейса продублирован в трёх местах (markdown-черновик,
пак war-room, пак холла), версии разъезжаются, поддерживать это нельзя.

Цель: **один продукт** — пошаговый воркшоп на сервере. Один пак на кейс —
единственный источник правды. Три экрана собираются из одного состояния:
проектор (инцидент и последствия), телефоны пяти ролей (приватные данные
и голосование), пульт ведущего (полная картина и управление).

War-room (реалтайм-автопилот) **удаляется** как отдельный продукт.

## Принятые решения

1. Механика — пошаговая, на сервере; телефоны у пяти ролей; бумажный
   фолбэк без телефонов.
2. Голосуют все пять ролей поровну; при ничьей решает Командир инцидента
   (его привилегия объявлена в лобби).
3. War-room и его движок удаляются (см. список в разделе «Удаляемое»).
4. Формат пака — JS-модуль (как текущие паки холла).

## Единый пак: формат данных

Один файл на кейс: `scenarios/<case>.js`, экспортирует объект:

```
{
  meta:    { id, title, difficulty, etaMin, moneyLimit }
  roles:   { <roleId>: { name, mission, welcomePrivate } }  // 5 ролей
  steps:   [ {
    id, title,
    brief:    строка — публичный текст инцидента (проектор)
    diagram:  { viewBox, boxes, arrows, focus } — как в hall-паках сейчас
    private:  { <roleId>: { data, deliver } }  // data — что видит роль,
              // deliver — «что донести команде»
    options:  [ {
      id, label,
      effects: { tension, moneyMin, ttrMin },   // дельты метрик
      score,                                   // очки
      trap: bool,                               // ловушка (не показывать залу)
      revealText,                              // «что случилось» (проектор)
      debrief                                  // «для разбора» (ведущий)
    } ]
    hint: строка — как подать шаг (только ведущему)
  } ]
  end:     { grades: [ {min, label} ], rootCause, debriefQuestions }
}
```

Пять ролей (id стабильны, названия только русские): `commander`
(Командир инцидента), `scout` (Скаут наблюдаемости), `engineer`
(Инженер платформы), `domain` (Доменный специалист), `comms`
(Связной с бизнесом).

Правила пака (валидатор):

- ровно 5 ролей, у каждого шага — приватный блок на каждую роль;
- 2–4 варианта на шаг, у каждого варианта — revealText, debrief,
  числовые effects и score;
- ровно один «лучший» вариант на шаг (max score, не trap);
- trap-варианты: hint не начинается со слова «Ловушк» (это маркер
  для тестов, как в hall-паках сейчас);
- `end.grades` покрывает диапазон 0..maxScore без дыр.

Markdown-черновики (`phantom-network-asymmetric.md`,
`expired-certificate-training.md`) остаются для чтения людьми, источником
правды становится пак; тест следит за согласованностью ключевых чисел.

## Три экрана

Все три — представления одного серверного состояния (SSE, как в текущем
`server.js`).

### Экран инцидента — проектор (`#screen`)

Зал, 20–200 человек, устройств не нужно. Показывает:

- таймлайн инцидента и три шкалы метрик: напряжение, деньги (потери, ₽),
  время (рост TTR, мин);
- текущий шаг: brief, диаграмма с фокусом на компоненте, вопрос и варианты
  (без подсказок и без правильных ответов);
- после раскрытия: анимация шкал по effects, вердикт («Лучший ход» /
  «Приемлемо» / «Слабый ход» / «Ловушка») — слово видит и зал, как сейчас
  в холле, но внутренний флаг trap и данные варианта не подсвечиваются;
  revealText, обновлённый счёт;
- финал: оценка по шкале из `end.grades`, итоговые метрики, пошаговый
  список «что выбрали vs что было лучшим», rootCause.

### Экран роли — телефон (`#play`)

Видит только владелец роли (вход по ссылке с выбором свободной роли,
первый занял — остальным закрыта; PIN не нужен):

- карточка роли: имя, миссия, приветственная приватка;
- на каждом шаге: свой блок `private[roleId]` (data + deliver);
- кнопки голосования — активны, пока открыто голосование;
- экран телефона показывать другим нельзя (правило озвучивает ведущий,
  дисциплина — как в жизни: данные передаются словами).

### Экран ведущего — ноутбук (`#gm`, защищён `GM_PIN`)

Видит всё, включая приватку всех пяти ролей. Зона действий сверху вниз:

- текущий шаг + hint «как подать»;
- ход голосования: «3/5: scout—B, engineer—A…»;
- управление раундом: открыть голосование → таймер → раскрыть
  последствия → дальше;
- сервисные действия: откат шага (undo очков/метрик/журнала), доголосовать
  за молчащую роль вручную, повторное голосование, переход к финалу;
- «Скопировать итоги» — Markdown-отчёт в буфер.

## Механика раунда

Один раунд ≈ 3–4 минуты, 8–10 шагов, игра 30–40 минут + разбор 10–15.

1. **Ситуация (30 сек).** Проектор: новый фрагмент, вопрос, варианты.
   Ведущий читает вслух.
2. **Приватка (1 мин).** Роли читают свой блок на телефонах.
3. **Обсуждение (90 сек).** Ведущий опрашивает роли по очереди; роль
   озвучивает приватку своими словами; зал давит советами; ведущий
   прижимает таймером.
4. **Голосование (30 сек).** Роли голосуют молча на телефонах; видит
   только ведущий. Все 5 проголосовали или таймаут → ведущий решает,
   что дальше (раскрыть / повторное голосование).
5. **Раскрытие (1 мин).** Ведущий жмёт «раскрыть»: проектор показывает
   последствия выбранного большинством варианта. При ничьей Командир
   называет финальный вариант, ведущий выбирает его на пульте.
6. **Мини-разбор (30–60 сек).** Комментарий ведущего по debrief → «дальше».

Ловушка, выбранная большинством, — не чинится: это материал разбора
(blameless). Откат возможен только сразу (ошибка ввода), по клавише/кнопке
undo, как в текущем холле.

## Сценарий ведущего

**Подготовка (5 мин):** `GM_PIN=4821 npm start`; проектор `#screen` + PIN;
свой ноутбук `#gm`; QR/адрес `#play` на проекторе; 5 добровольцев занимают
роли; зал называет команду (вбивается с пульта); на пульте «5/5 на местах»
→ старт.

**Ход:** раунды по схеме выше. Инструменты влияния ведущего: очерёдность
опроса, таймер, пауза перед раскрытием («Связной, ты против всех —
убеди команду или сдашься?»), повторное голосование при расколе.

**Финал:** оценка по `end.grades`, итоговые метрики, пошаговый разбор
(долгие шаги первыми), «Скопировать итоги», вопросы из
`end.debriefQuestions` залу.

## Бумажный фолбэк

Если телефоны недоступны (гостевой Wi-Fi, репетиция): приватка печатается
карточками из того же пака, голосование — поднятием рук, ведущий вбивает
5 голосов на пульте вручную. Игра не ломается: тот же пак, тот же
проектор, режим «бумага».

## Сервер и состояние

Переиспользуется текущий `server.js`: SSE-рассылка, комнаты, state.json
(восстановление после падения), `GM_PIN`, `/healthz`. Состояние сессии:

```
{ scenarioId, stepId, phase, votes: {roleId: optionId},
  revealed: optionId|null, score, metrics, journal, status }
```

`phase`: `lobby | situation | discussion | voting | revealed | debrief | end`.
Любая вкладка пульта — источник команд; проектор и телефоны — read-only
(кроме голоса роли).

## Миграция контента

Два кейса переписываются в новый формат. Единые паки займут имена
`scenarios/phantom-network.js` и `scenarios/expired-cert.js`: текущие
файлы с этими именами (паки war-room) удаляются, на их место встают
единые паки (скелет шагов/ролей/диаграмм — из нынешних hall-паков,
приватные данные — из war-room паков и markdown-черновиков). Старые
hall-паки (`scenarios/hall-*.js`) удаляются. В результате — ровно один
пак на кейс.

## Тестирование

- валидатор паков (правила из раздела «Единый пак»);
- движок: тай-брейк Командира, кворум, откат, подсчёт метрик и оценок,
  невозможность голоса дважды;
- сервер: фазы, рассылка по SSE, PIN-проверка пульта, восстановление из
  state.json;
- UI-тесты по существующему образцу `test-ui/` на три экрана.

## Крайние случаи

| Ситуация | Решение |
|---|---|
| Телефон роли не открылся | Карточка-распечатка; голос вбивает ведущий |
| Роль молчит | Таймер → на пульте подсвечено ключевое из её приватки, озвучивает ведущий |
| Падение сервера посреди игры | state.json, рестарт продолжает с того же шага |
| Зал переспорил роли, выбор плохой | Не чинить, разобрать (blameless) |
| Попытка открыть `#gm` с телефона зала | PIN; деструктивные действия с подтверждением |

## Вне рамок

- Несколько команд за столами, соревновательный режим;
- авторассадка ролей по жребию на сервере (сейчас — «кто первый»);
- сетевой режим между площадками.
