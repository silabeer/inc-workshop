# Холл-режим: «Решение за решением» с ролями — дизайн v1.1

Дата: 2026-10-07 (v1.0), пересмотр 2026-10-09 (v1.1: одна команда + роли + диаграммы).
Статус: утверждено пользователем.

## Контекст и проблема

War-room (`war-room.html` + сервер) — реальное время, станции, ключи K1–K6; для живого
зала тяжело. Холл-режим v1.0 (дуэль двух команд) оказался слишком «новеллой»: из
тренировки выпала ролевая механика инцидента. v1.1: одна команда зала, внутри которой
работают роли из исходных паков; темп диктует ведущий, техника — одна кнопка.

Принцип: **шаг диктует роль-владелец, темп — ведущий, техника — одна кнопка.**

## Концепция

Интерактивный тренировочный инцидент для зала. Кейс — граф из 8–12 узлов-решений.
Проектор показывает ситуацию, диаграмму архитектуры системы и варианты действий.
Каждый узел имеет владельца-роль: этот человек ведёт шаг (читает экран вслух,
собирает мнение зала, называет выбор). Ведущий жмёт выбор (или владелец — с клавиатуры),
экран показывает последствия, «Дальше» — следующий узел.

## Игровые правила

- Одна команда (имя редактируется в лобби, дефолт «Команда зала»). Внутри — роли:
  **Командир инцидента, Скаут наблюдаемости, Инженер платформы, Доменный специалист,
  Связной**. Роли только на русском. Людей больше пяти — роли можно держать вдвоём.
- У каждого узла (кроме `end`) — владелец-роль `role` и задача роли `roleTask`
  (что делает роль на этом шаге). Все пять ролей должны встречаться в кейсе.
- Очки: один командный счёт. Варианты оценены: лучший +2, приемлемый +1, плохой 0,
  катастрофа −1. «Ловушки» — варианты с явным флагом `trap: true` (см. Формат сценария).
- Шкала напряжения tension 0–100, старт 50; каждый выбор двигает её (кламп 0–100).
  Пороги цвета в UI: <40 зелёный, 40–70 жёлтый, >70 красный.
- Финал: узел `end`. Итоговый экран: текст концовки + метрики — очки, число ловушек
  (выборы с score < 0), финальное напряжение. Победителя/ничьей нет.

## Формат сценария

Обычный script-файл (не ES-модуль), регистрация через глобальный коллектор
`HALL_SCENARIO(obj)`:

```js
HALL_SCENARIO({
  id: 'hall-phantom-network',
  title: 'Фантомная сеть и шторм повторов',
  brief: '...',                       // описание в лобби
  start: 'p1',
  roles: {                            // роли кейса, только русские имена
    commander: { name: 'Командир инцидента', short: 'Командир', desc: 'Ведёт доску гипотез…' },
    scout:     { name: 'Скаут наблюдаемости', short: 'Скаут', desc: '…' },
    platform:  { name: 'Инженер платформы', short: 'Платформа', desc: '…' },
    domain:    { name: 'Доменный специалист', short: 'Домен', desc: '…' },
    comms:     { name: 'Связной', short: 'Связной', desc: '…' },
  },
  diagram: {                          // архитектура, нарисованная вручную («архитектором»)
    nodes: [ { id:'edge', label:'edge-gateway', x:200, y:130, color:'red', note:'5xx 92%' } ],
    edges: [ { from:'edge', to:'order', label:'' } ],   // координаты — viewBox 640×320
  },
  nodes: {
    p1: {
      id: 'p1', title: '...', text: '...',    // ситуация
      role: 'commander',                      // владелец шага
      roleTask: 'Объявите инцидент и заведите доску гипотез.',
      say: '...',                             // опционально, что сказать залу
      choices: [ { id, label, score, tension, outcome, hint, goto } ],  // 2–4 штуки
    },
    pEnd: { id: 'pEnd', end: true, title: '...', text: '...' },
  },
});
```

Ветвление допускается, из каждого узла достижим хотя бы один `end`.

## Движок hall-engine.js

UMD как раньше. Чистые функции, без DOM/дат/хранилищ. `choose` не мутирует вход.

- `validate(scn) → string[]` — старт существует; 2–4 варианта у не-`end` узлов; `goto`
  существуют; из каждого узла достижим `end`; блок `roles` непустой; у каждого не-`end`
  узла есть `role` (известная роль) и непустой `roleTask`; `diagram` присутствует, id
  узлов диаграммы уникальны, рёбра ссылаются на существующие узлы, координаты — числа.
- `createGame(scn, opts?) → state`, `opts.team?: string` (дефолт «Команда зала»).
  state: `{scenarioId, nodeId, team, score: 0, tension: 50, log: [], status: 'ACTIVE'}`;
  log-запись: `{nodeId, choiceId, gained, tension, trap}` (`trap` — копия флага варианта).
- `choose(state, choiceId) → {state, result}`; result: `{choice, gained, tension}`.
  Кламп tension; при попадании в `end` — `status: 'ENDED'`. Бросает `Error` на
  неизвестном `choiceId` и на `state.status === 'ENDED'`.

Вариант выбора может нести `trap: true` — явная пометка ловушки. Метрика «Ловушки»
на финале и счётчик в игре считают выборы с этим флагом (не отрицательные очки).

## UI hall.html

Один самодостаточный файл, работает по file:// без сервера; состояние в памяти;
рестарт возвращает в лобби (имя команды сохраняется). Подключает `hall-engine.js`
и сценарии обычными `<script src>`; коллектор `window.HALL_SCENARIO` определяется
до подключения сценариев.

Экраны:
1. **Лобби** — карточки кейсов (title + brief + мини-диаграмма), поле имени команды,
   «Старт».
2. **Игровой** — заголовок кейса и узла; бейдж «Шаг: <роль, русское имя>»; tension-
   полоса; карточка ситуации; варианты с цифрами 1–4; командный счёт + счётчик
   ловушек; **панель диаграммы архитектуры** (SVG, построенный из `diagram`,
   viewBox 640×320, цвета компонентов по `color`); в углу мелко — `say` и `roleTask`.
3. **Последствия** — outcome, «+N очков», дельта tension, мелко `hint`, «Дальше».
4. **Финал** — текст end-узла, метрики (очки, ловушки, напряжение), «Заново».

Горячие клавиши: 1–4 — выбор, Enter/→ — дальше, R — в лобби; обработчик игнорирует
события из INPUT/TEXTAREA.

## Контент

Оба hall-кейса дополняются: блок `roles` (имена и описания — из исходных паков,
переведённые), теги `role` и строки `roleTask` на каждом узле (из пошаговых `hints`
исходных паков), ручные диаграммы архитектуры. Все пять ролей в каждом кейсе
должны вести хотя бы один шаг. Оригинальные паки и war-room не изменяются.

## Тестирование

- `test/hall-engine.test.js` — валидация (включая роли и диаграммы); дефолты
  `createGame`; `choose` начисляет в командный счёт; tension кламп; исключения;
  иммутабельность; переход в `end` → `ENDED` без победителя.
- `test/hall-packs.test.js` — оба пакета проходят `validate` пусто; прохождение
  первым вариантом до `end` → `ENDED`; сумма `log[].gained` == итоговый `score`;
  все пять ролей присутствуют среди узлов.
- `test/hall-ui.test.js` — инлайн-скрипты парсятся; подключены движок и оба сценария;
  file://-безопасность (нет fetch/localStorage/модулей); guard INPUT в keydown;
  наличие рендера диаграммы.
- Прогон: `node --test --test-force-exit`.

## Границы (не делаем)

Сервер, архив, автопилот, реальное время, паузы, ключи K1–K6, localStorage, дуэль
команд, английские имена ролей, асимметрия «каждый видит только свой кусок», редактор
сценариев, динамические статусы на диаграмме (статичная картинка на весь кейс).

## Критерии приёмки

- `hall.html` открывается по file://, оба кейса проходимы до конца, диаграмма видна.
- Все пять ролей (на русском) ведут шаги в каждом кейсе; ведущий управляет с клавиатуры.
- `node --test --test-force-exit` — все тесты зелёные.
- `war-room.html`, `server.js`, `engine.js`, исходные пакеты — не изменены.
