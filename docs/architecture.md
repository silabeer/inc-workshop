# Архитектура

Проект без зависимостей и без сборки: браузер получает файлы как есть, Node нужен для сервера и тестов.

```
 /#screen  проектор ─┐                         ┌─▶ DATA_DIR/state.json
 /#play    телефоны ─┼─ SSE /events?view=… ◀── server.js ──▶ DATA_DIR/archive/*.json
 /#gm      пульт    ─┘   POST /api/{claim,vote,cmd} ──▶ │
                                                       └── workshop-engine.js  ◀── scenarios/*.js
```

## Сервер — источник правды

Одна сессия на сервер (одна игра за раз). Браузеры не хранят и не вычисляют состояние игры:
они шлют **команды** и получают **представления**.

- `POST /api/claim {role, token}` — телефон занимает роль. Занята другим токеном → 409.
- `POST /api/vote {role, token, option}` — голос роли. Токен не совпадает с местом → 403.
- `POST /api/cmd {type, …}` с заголовком `x-gm-pin` — команды пульта: `team`, `start`,
  `discussion`, `voting`, `revote`, `vote` (за роль), `reveal` (`option` — явный выбор),
  `next`, `finish`, `undo`, `release`, `reset` (`scenarioId` — новая партия).
- Ошибки правил (не та фаза, голос дважды, ничья без выбора) — 400 с текстом по-русски;
  интерфейс показывает его тостом.

Сервер применяет команду движком (`apply`), сохраняет состояние атомарно
(запись во временный файл и rename) и рассылает каждому SSE-клиенту его представление.
Конкурирующих записей нет: Node обрабатывает команды по одной, поэтому версии и 409 по ревизии не нужны.

### Представления

`GET /events?view=screen|play|gm` — поток, где каждое сообщение — полное представление для этого экрана.

| Представление | Содержит | Не содержит |
| --- | --- | --- |
| `screen` | ситуацию, варианты (id, текст), кто проголосовал, метрики, диаграмму; после раскрытия — вердикт и последствия; в финале — итоги и причину | приватку, голоса по ролям, очки и флаги вариантов, подсказки |
| `play&role&token` | карточку и приватку своей роли, свой голос | чужую приватку и голоса; с чужим токеном — ничего ролевого |
| `gm&pin` | всё: приватку всех ролей, голоса, подсчёт, разбор вариантов, журнал, отчёт, каталог кейсов | — |

Паки в браузер не отдаются вовсе (`/scenarios/` — 404). Полный пак получает только пульт —
`GET /api/pack` с PIN, для печати карточек.

Каждое представление несёт `now` — время сервера: клиент считает таймер фазы по нему, а не по своим часам.

## Движок

`workshop-engine.js` — UMD-модуль из чистых функций без DOM, сети и часов (время — аргумент `now`):

- `validate(pack)` — правила формата (см. `docs/scenario-authoring.md`);
- `createSession(pack, {team, seats})`, `apply(pack, state, cmd, now)` — переходы; бросает ошибку
  с `userError`, не трогая вход;
- `tally` — подсчёт голосов, кворум, тай-брейк Командира;
- `view(pack, state, audience, {role, token, now})` — представления;
- `summary`, `report` — итоги и Markdown-отчёт.

Фазы: `lobby → situation → discussion → voting → revealed → (следующий шаг: situation) … → end`.
Обсуждение можно пропустить, к итогам можно перейти досрочно.

**Откат.** Каждое управляющее действие кладёт снимок состояния в `history` (до 40). `undo`
возвращает последний снимок целиком — очки, метрики, журнал, голоса, фазу — кроме мест ролей:
освобождённая ведущим роль не возвращается откатом.

**Места ролей** — `seats: {role: token}` в состоянии. Токен генерирует телефон и хранит в
`localStorage`; перезагрузка или рестарт сервера возвращают роль без участия ведущего.

## Восстановление и архив

`state.json` хранит `{scenarioId, session}`. После рестарта сервер продолжает с того же шага и фазы.
`reset` пишет сыгранную партию в `archive/<время>-<кейс>.json` (`summary` + `session`), если она
начиналась, и создаёт новую с той же командой и местами. `GET /archive` — список, `GET /archive/<файл>` — партия.

## Модель безопасности

Рассчитана на локальную Wi-Fi воркшопа, не на интернет.

- Пульт и полный пак — только с `GM_PIN` (заголовок или параметр SSE-потока). Без `GM_PIN`
  сервер предупреждает при старте и на пульте.
- Телефоны и проектор работают без PIN, но видят только своё: приватка не уходит туда, где её не должно быть.
- Голос принимается только от токена, занявшего роль.
- Тела запросов ограничены 100 КБ, статика раздаётся по белому списку каталогов (`ui/`, `fonts/`)
  и расширений, контент вставляется в DOM только как текст.

## Интерфейс

`index.html` — разметка и стили; `ui/common.js` — построение DOM, связь (EventSource +
переподключение), таймер, диаграмма, шкалы, перехват ошибок рендера; `ui/screen.js`, `ui/play.js`,
`ui/gm.js` — три экрана; `ui/app.js` — выбор экрана по хэшу (без хэша: телефон → роль, большой экран → пульт).

Ошибка рендера не замораживает экран молча: баннер «Экран сломался — обновите страницу».
Потеря связи — баннер «переподключаемся».

## Тесты

- `test/server.test.js` — HTTP-раунд, PIN, токены ролей, SSE-рассылка, отсутствие утечек, восстановление, архив, статика;
- `test/packs.test.js` — реальные паки: валидатор, лучший и худший пути, лимит потерь, согласованность с документами ведущего;
- `test-ui/` — Playwright: целая партия с проектором, пультом и телефонами, контраст, кегли, 720p, телефон 390 px.
