# Архитектура

Проект без зависимостей и без сборки: браузер получает файлы как есть, Node нужен для сервера и тестов.

```
 /#screen  проектор ─┐                              ┌─▶ DATA_DIR/state.json (все комнаты)
 /#play    телефоны ─┼─ SSE /events?room&view=… ◀── server.js ──▶ DATA_DIR/archive/*.json ──▶ analytics.js
 /#gm      пульт    ─┘   POST /api/{claim,vote,audience,cmd,rooms} ──▶ │
                                                            └── workshop-engine.js  ◀── scenarios/*.js
```

## Сервер — источник правды

Браузеры не хранят и не вычисляют состояние игры: они шлют **команды** и получают **представления**.

### Комнаты

Каждая комната — отдельная партия: свой пак, сессия и код входа. Комната `main` живёт на корне `/`,
остальные — на `/r/<комната>/` (латиница, цифры, дефис; до 20 комнат). Страница одна и та же, клиент берёт
комнату из адреса и передаёт её параметром `room` во все запросы. Создание и удаление —
`POST /api/rooms {action: create|delete, id}` с PIN; удаление архивирует партию. PIN ведущего общий для сервера.

- `POST /api/claim {role, token, code}` — телефон занимает роль; `role: "any"` — жребий среди свободных
  (повтор с тем же токеном возвращает ту же роль). Занята другим токеном → 409, неверный код входа → 403.
- `POST /api/vote {role, token, option}` — голос роли. Токен не совпадает с местом → 403.
- `POST /api/audience {token, option, code}` — голос зрителя: один на устройство за шаг, до 1000 на шаг,
  только в фазе голосования; устройство с ролью голосует как роль. На решение не влияет.
- `POST /api/cmd {type, …}` с заголовком `x-gm-pin` — команды пульта: `team`, `start`,
  `discussion`, `voting`, `revote`, `vote` (за роль), `reveal` (`option` — явный выбор),
  `next`, `finish`, `undo`, `release`, `reset` (`scenarioId` — новая партия), `shuffle` (жребий мест,
  перестановку выбирает сервер через `crypto.randomInt`), `sound` (`on`), `joinCode` (`code`, пусто — выключить).
- Ошибки правил (не та фаза, голос дважды, ничья без выбора) — 400 с текстом по-русски;
  интерфейс показывает его тостом.

Сервер применяет команду движком (`apply`), сохраняет состояние атомарно
(запись во временный файл и rename) и рассылает каждому SSE-клиенту его представление.
Конкурирующих записей нет: Node обрабатывает команды по одной, поэтому версии и 409 по ревизии не нужны.

### Представления

`GET /events?view=screen|play|gm` — поток, где каждое сообщение — полное представление для этого экрана.

| Представление | Содержит | Не содержит |
| --- | --- | --- |
| `screen` | ситуацию, варианты (id, текст), кто проголосовал, метрики, диаграмму; после раскрытия — вердикт и последствия; в финале — итоги и причину | приватку, голоса по ролям, очки и флаги вариантов, подсказки |
| `play&role&token` | карточку и приватку своей роли, свой голос | чужую приватку и голоса; с чужим токеном — ничего ролевого |
| `play&token` (зритель) | вопрос и варианты, свой голос зрителя, число голосов зала | приватку, голоса ролей |
| `gm&pin` | всё: приватку всех ролей, голоса, подсчёт, разбор вариантов, журнал, отчёт, каталог кейсов | — |

Паки в браузер не отдаются вовсе (`/scenarios/` — 404). Полный пак получает только пульт —
`GET /api/pack` с PIN, для печати карточек.

Каждое представление несёт `now` — время сервера: клиент считает таймер фазы по нему, а не по своим часам.

## Движок

`workshop-engine.js` — UMD-модуль из чистых функций без DOM, сети и часов (время — аргумент `now`):

- `validate(pack)` — правила формата (см. `docs/scenario-authoring.md`);
- `createSession(pack, {team, seats})`, `apply(pack, state, cmd, now)` — переходы; бросает ошибку
  с `userError`, не трогая вход;
- `tally` — подсчёт голосов, кворум, тай-брейк Командира;
- `view(pack, state, audience, {role, token, now})` — представления;
- `summary`, `report` — итоги и Markdown-отчёт.

Фазы: `lobby → situation → discussion → voting → revealed → (следующий шаг: situation) … → end`.
Обсуждение можно пропустить, к итогам можно перейти досрочно.

**Откат.** Каждое управляющее действие кладёт снимок состояния в `history` (до 40). `undo`
возвращает последний снимок целиком — очки, метрики, журнал, голоса, фазу — кроме мест ролей:
освобождённая ведущим роль не возвращается откатом.

**Голоса зала** — `audience: {token: option}` на текущем шаге; обнуляются с новым голосованием и шагом.
При раскрытии распределение (`counts`, `total`, `leader`) записывается в журнал шага: оттуда его берут
проектор, итоги, отчёт и аналитика. До раскрытия проектор показывает только число голосов зала.

**Места ролей** — `seats: {role: token}` в состоянии. Токен генерирует телефон и хранит в
`localStorage`; перезагрузка или рестарт сервера возвращают роль без участия ведущего.

## Восстановление, архив, аналитика

`state.json` хранит `{version: 3, rooms: {id: {scenarioId, session, joinCode}}}` (файл формата 2.0
с одной партией подхватывается как комната `main`). После рестарта сервер продолжает с того же шага и фазы.

Партия пишется в архив при переходе в итоги и при старте новой партии (если в ней был хотя бы один шаг).
Имя файла — время старта партии, комната и кейс, поэтому повторная запись (откат и снова итоги) перезаписывает
тот же файл. Токены устройств и голоса зала по токенам в архив не попадают. `GET /archive`, `GET /archive/<файл>`
и `GET /api/analytics` — только ведущему. `analytics.js` — чистая функция `aggregate(записи, паки)`:
средний счёт, потери и TTR, частота ловушек, доля лучших ходов и среднее время по шагам, совпадение зала с ролями.

## Модель безопасности

По умолчанию — локальная Wi-Fi воркшопа. Для игры через интернет есть сетевой режим.

- Пульт, полный пак, архив и аналитика — только с `GM_PIN` (заголовок или параметр SSE-потока),
  сравнение за постоянное время. Без `GM_PIN` сервер предупреждает при старте и на пульте.
- **Защита от перебора:** 10 неверных PIN за 10 минут — адрес получает 429 на 10 минут с последней неудачи;
  коды входа считаются отдельно (адрес + комната), поэтому опечатки зала не запирают пульт. PIN сравнивается
  по SHA-256 за постоянное время (любые байты в заголовке безопасны). За прокси адрес — самый правый в
  `X-Forwarded-For` и только при `TRUST_PROXY=1`. Таблица неудач ограничена и вытесняет старые записи.
- **Нагрузка:** голосов зала — не больше 50 с адреса за шаг и 1000 на шаг; их рассылка и запись состояния
  идут пачкой раз в 300 мс. Потоков SSE — до 200 с адреса и 3000 всего.
- **Устойчивость:** ошибка построения одного представления пишется в лог и не роняет процесс; партия в
  `state.json`, не сходящаяся с исправленным паком, при старте заменяется новой.
- **Адрес для телефонов:** `PUBLIC_URL`, иначе — адрес, с которого открыт проектор (если не localhost),
  иначе — адреса ноутбука в локальной сети. С `PUBLIC_URL` `/api/info` не раскрывает внутренние адреса.
- **Код входа** комнаты (4–12 латинских букв или цифр) требуется для занятия роли и голоса зрителя.
  Проектор знает только факт, что код есть; сам код видит пульт.
- **HTTPS:** `TLS_CERT` и `TLS_KEY` — сервер поднимает TLS сам и ставит HSTS; либо прокси с HTTPS.
- Телефоны и проектор видят только своё: приватка не уходит туда, где её не должно быть.
  Голос роли принимается только от токена, занявшего роль.
- Заголовки: CSP (`script-src 'self'`, без встраивания в чужие страницы), `nosniff`, `no-referrer`, `X-Frame-Options: DENY`.
- Тела запросов ограничены 100 КБ, статика раздаётся по белому списку каталогов (`ui/`, `fonts/`)
  и расширений, контент вставляется в DOM только как текст.

## Интерфейс

`index.html` — разметка и стили; `ui/common.js` — построение DOM, связь (EventSource +
переподключение), комната из адреса, таймер, диаграмма, шкалы, QR-код, звук (WebAudio), перехват ошибок рендера;
`ui/qr.js` — QR-кодер без зависимостей (байтовый режим, коррекция M, версии 1–10); `ui/screen.js`, `ui/play.js`,
`ui/gm.js` — три экрана, карточки и аналитика; `ui/app.js` — выбор экрана по хэшу (без хэша: телефон → роль,
большой экран → пульт).

Ошибка рендера не замораживает экран молча: баннер «Экран сломался — обновите страницу».
Потеря связи — баннер «переподключаемся».

  контраст, кегли, 720p, телефон 390 px.
