# inc-workshop — тренажёр инцидент-респонса для живых воркшопов

Команда дежурных разбирает боевой инцидент: ищет причину по данным, обходит ловушки
(откат «виноватого» релиза, раздувание пула, WAF против «DDoS»), держит коммуникацию
с бизнесом и закрывает инцидент по критерию, а не по вспышке зелёного графика.

Один пошаговый воркшоп, три экрана из одного состояния на сервере:

| Экран | Адрес | Кто видит | Что показывает |
| --- | --- | --- | --- |
| Проектор | `/#screen` | Весь зал, 20–200 человек | Ситуация, диаграмма, варианты без подсказок, шкалы напряжения, потерь и TTR, последствия, итоги |
| Телефон роли | `/#play` | Пять игроков, каждый свою роль | Приватные данные роли на шаге, «что донести команде», голосование |
| Пульт ведущего | `/#gm` | Только ведущий (PIN) | Приватка всех ролей, голоса, подсказки «как подать», разбор вариантов, управление раундом |

Пять ролей голосуют поровну, при ничьей решает Командир инцидента. Данные у ролей разные:
лучшее решение складывается, только если роли пересказывают свои данные словами.
Если телефонов нет, карточки ролей печатаются из того же пака, а голоса ведущий вписывает сам.

Игра длится 30–40 минут, разбор ещё 10–15.

## Быстрый старт

Нужен Node.js 18+. Зависимостей нет, `npm install` не требуется.

```bash
GM_PIN=4821 npm start     # = node server.js, порт 8085
```

Сервер печатает адреса:

- `http://localhost:8085/#screen` — проектор;
- `http://localhost:8085/#gm` — пульт ведущего (PIN из `GM_PIN`);
- `http://<ip-ноутбука>:8085/#play` — телефоны ролей в той же Wi-Fi (адрес крупно показан на проекторе в лобби).

### Docker

```bash
docker build -t inc-workshop .
docker run -d -p 8085:8085 -e GM_PIN=4821 -v inc-workshop-data:/app/data inc-workshop
```

Состояние партии и архив сыгранных партий лежат в томе `/app/data`. Если сервер упадёт,
после рестарта игра продолжится с того же шага, роли останутся за своими телефонами.
Проверка живости: `GET /healthz`.

Переменные окружения: `PORT` (8085), `HOST` (0.0.0.0), `DATA_DIR` (каталог проекта),
`GM_PIN` (PIN пульта; без него пульт открыт всем в сети).

## Кейсы

| Кейс | Шаги | О чём |
| --- | --- | --- |
| Просроченный сертификат | 8 шагов, ~30 минут | Истёкший TLS на edge, а все смотрят на вчерашний релиз. Для первого знакомства |
| Фантомная сеть и шторм повторов | 10 шагов, ~40 минут | Эквайер молчит без FIN/RST, вызовы без таймаутов, мобильный клиент добивает ретраями |

Пак кейса (`scenarios/*.js`) — единственный источник правды. Документы ведущего с полной фактурой
(игрокам не показывать) остаются для чтения людьми, тест сверяет с ними ключевые числа:
[`expired-certificate-training.md`](expired-certificate-training.md),
[`phantom-network-asymmetric.md`](phantom-network-asymmetric.md).

## Разработка

```bash
npm test                # = node --test; CI гоняет Node 18 и 22
npm run validate        # проверить паки; один пак: node tools/validate.js scenarios/x.js

# UI-проверки в браузере (контраст, кегли проектора, телефон, 720p) + скриншоты в test-ui/out/
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt && .venv/bin/playwright install chromium
npm run test:ui
```

Правила интерфейса — проектный скилл [`.claude/skills/inc-workshop-ui`](.claude/skills/inc-workshop-ui/SKILL.md).

```
server.js               HTTP + SSE: команды, представление для каждого экрана, state.json, архив
workshop-engine.js      движок: валидация пака, раунд, голосование, подсчёт, итоги (чистые функции)
index.html              разметка и стили трёх экранов
ui/                     common.js (DOM, связь, диаграмма), screen.js, play.js, gm.js, app.js (маршруты)
theme.css, fonts/       токены оформления и локальные шрифты
scenarios/*.js          паки кейсов (один файл на кейс)
tools/validate.js       проверка паков из командной строки
test/                   node:test, без фреймворков
test-ui/                Playwright-проверки интерфейса (Python), запуск npm run test:ui
```

Правила для разработчиков и агентов — в [`CLAUDE.md`](CLAUDE.md).
